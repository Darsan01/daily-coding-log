# Day 2 — Valid Anagram (Python)

**Date:** 2026-10-27
**Topic:** Valid Anagram — hash map character counts
**Code:** [`valid_anagram.py`](valid_anagram.py)

## Problem

Given two strings `s` and `t`, return `true` if `t` is an anagram of `s`,
and `false` otherwise. An anagram uses exactly the same letters, the same
number of times, in a different order.

**Example:** `s = "anagram"`, `t = "nagaram"` → `true`.
**Example:** `s = "rat"`, `t = "car"` → `false`.

## Key idea

Two strings are anagrams when their letter frequencies match. Count the
characters of `s` into a hash map, then walk through `t` decrementing the
counts. If a character in `t` is missing or its count drops below zero,
the strings can't be anagrams. A quick length check up front handles the
trivially different case.

The alternative — sorting both strings and comparing — is simpler to write
but costs O(n log n) time. Counting is linear and the classic interview
answer; it is also the same hash-map thinking as Day 1's Two Sum, applied
to frequencies instead of complements.

## Complexity

- **Time:** O(n) — one pass over each string to count and compare.
- **Space:** O(k) — the hash map holds at most one entry per distinct
  character (k ≤ 26 for lowercase English letters, so effectively O(1)).

## What I practised

- Building a frequency map with `dict.get(ch, 0) + 1`.
- Early exits: length mismatch and negative counts.
- Comparing two approaches (counting vs sorting) and knowing when the
  faster one is worth the extra code.
